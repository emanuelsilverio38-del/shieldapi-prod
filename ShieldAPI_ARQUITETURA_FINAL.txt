ShieldAPI - Arquitetura Final Profissional

1. Objetivo

A ShieldAPI e uma API profissional para Solana focada em seguranca, inteligencia e decisao antes de qualquer bot, agente IA, screener ou aplicacao interagir com um token.

Decisao central:

- APPROVED
- WARNING
- BLOCKED

Com:

- riskScore
- securityScore
- opportunityScore
- reasons
- warnings
- blockingReasons
- dados de mercado
- checks de seguranca
- futuramente quote/swap seguro sem guardar private keys

Posicionamento:

Security and intelligence API for Solana AI agents, trading bots and token scanners.

Frase comercial:

Antes do teu bot, agente ou scanner interagir com um token Solana, chama a ShieldAPI.

Promessa correta:

Reduce bad-token exposure before your bot, agent or app interacts with a Solana token.

3. Responsabilidade do server.js

O server.js deve ser apenas bootstrap/entrada da aplicacao.

Deve fazer:

- carregar env/config
- criar servidor HTTP
- inicializar DB
- criar routeContext
- chamar handleRoute()
- tratar OPTIONS/CORS
- tratar fallback 404
- tratar SIGTERM
- iniciar server.listen

Nao deve conter no estado final:

- SQL grande
- Stripe grande
- Dexscreener logic grande
- risk engine
- scoring
- admin logic pesada
- billing webhook completo
- auth pesado
- cache logic grande
- scanner logic
- execution logic

23. Regras Obrigatorias de Seguranca

- Nunca guardar private keys dos clientes
- Nunca imprimir API keys completas nos logs
- Usar hash SHA-256 das API keys
- Proteger endpoints admin com admin key
- Validar Stripe webhook signature
- Nao confiar em dados enviados pelo cliente
- Validar enderecos Solana
- Aplicar rate limit
- Aplicar quota
- Ter timeouts em APIs externas
- Ter fallback quando Dexscreener/RugCheck falham
- Nao prometer lucro
- Nao apresentar como aconselhamento financeiro
